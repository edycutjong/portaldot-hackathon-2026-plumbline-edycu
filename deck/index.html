Today one way to find out is to submit a transaction and read the error. The next runtime upgrade moves the line again.

STA. 03

Proof

A canary extrinsic is signed and sent, its receipt kept, then re-read from its block by hash in a new process. PROVEN needs that receipt.

$ plumbline canary
$ plumbline readback
PROVENUNPROVENARGS-UNCHECKED ARG_DRIFTDRIFTEDABSENT verdicts from plumbline/verdicts.py

Beside the flow: plumbline diff A B lists what moved between two runtimes; plumbline check <dApp> --target v3 classifies a dApp's call sites against one, with exit codes 0 / 1 / 2.

Three steps. Read what the docs and the V3 guide say exists. Join each entry to the runtime's own metadata and write exactly one verdict. Only a transaction that went through and was read back from its block can turn a verdict into PROVEN.
