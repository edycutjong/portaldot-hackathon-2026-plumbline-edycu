Questions a judge asks

Short answers; the README and docs/PROOF.md carry the long ones.

Is this V3, or a stand-in?

Profile v3 is the live Portaldot V3 testnet, spec 3002, measured 2026-10-19. A local upstream dev chain (interim-sdk) is kept as test input and labelled not V3 everywhere it appears.

Does it send transactions?

Only plumbline canary sends transactions: 3 on V3 with a funded seed file (blocks 106424–106426), read back 3/3, plus a local stand-in run with dev keys that is labelled not V3. Everything else is read-only RPC. The canary refuses the mainnet profile.

What does PROVEN mean?

A canary for that call succeeded on that runtime and was re-read from its block by hash. 3 of the 196 mainnet-docs calls are PROVEN on V3.

Why are 191 calls UNPROVEN, not “OK”?

They exist on V3 by name and arguments, but no transaction was sent for them. The ledger says what it could not establish instead of rounding it up.

Can I run it on my dApp?

plumbline check <dir> --target v3 gives one verdict per call site and exits 0, 1 or 2 (1 = blocking findings). The repo’s example dApp: 9 findings, blocking 0 on V3, blocking 5 on mainnet spec 1002.

What happens at the next runtime upgrade?

Re-run it. plumbline diff lists what moved (516 rows from mainnet spec 1002 to V3), and the ledger is regenerated against the new metadata.
